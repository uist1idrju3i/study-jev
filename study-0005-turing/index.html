RESEARCH NOTES — what “Turing complete” means

Definition

  • A system of data-manipulation rules (a language, machine, instruction set, cellular automaton…) is Turing-complete if it can simulate an arbitrary Turing machine — equivalently, if it can compute every Turing-computable function (Church–Turing thesis).
  • To prove completeness it suffices to simulate any one known-complete system: a universal Turing machine, a two-counter (Minsky) machine, a cyclic-tag system, Rule 110, or the lambda calculus.

Practical ingredients

  • Sequencing + conditional branching — execute blocks in order and pick between two paths on a condition.
  • Unbounded repetition — while-loops, recursion, self-reapplication, or any mechanism that can run forever. A system that guarantees termination (a “total” language like Dhall or the total fragments of Coq/Agda) cannot be Turing-complete.
  • Unbounded read/write storage — memory with no fixed a-priori bound: a tape, a heap, two stacks, growing lists. One pushdown stack alone is not enough (that yields only context-free power); two stacks suffice.

Caveats when judging

  • Unbounded ≠ infinite. No physical machine is strictly Turing-complete (all have finite memory — technically they are linear-bounded automata). The convention is to judge the abstract model as if memory were unbounded, so real computers count.
  • Bounded variants. Fixed-size tapes/grids or fixed-width integers make a system formally not complete, yet it is conventionally called complete (e.g. real C with bounded pointers, Befunge-93’s 80×25 grid).
  • Externally driven systems. HTML+CSS3 can run Rule 110 but only with a human clicking to step generations; the C preprocessor needs its output re-fed in a loop. These are “complete when externally iterated” — a gray zone.
  • Property of the model, not the program. A single terminating program is not Turing-complete; the language or machine it runs on may be.
  • Undecidability. Deciding whether an arbitrary system is Turing-complete is itself undecidable — any verdict here is calibrated inference, not a proof.

Reference points

  • Turing-complete: general-purpose languages, brainfuck, Conway’s Game of Life, Rule 110, Excel, Minecraft redstone, Factorio, Dwarf Fortress, Magic: The Gathering, PowerPoint animations, C++ templates, the TypeScript/Scala/Java type systems, sed/awk, printf format strings, x86 MMU page-fault handling, PostScript, SQL with recursive CTEs, Apache mod_rewrite, Wang tiles, (infinite) Minesweeper, Vim normal mode.
  • Not Turing-complete: finite-state automata, classic regular expressions, a single-stack pushdown automaton (context-free), straight-line arithmetic, propositional logic, static markup/data formats (HTML alone, JSON, Markdown), SQL-92 without recursion, XPath 1.0, total languages (Dhall, Charity), early CSS alone.

How this page asks

  • score — rates the description on five ordered levels from “clearly not” to “clearly”; the answer carries a continuous score (0–4), a probability per level, and confidence. Normalized to 0–1 as score/4.
  • noul — answers “is it Turing-complete?” as the probability of yes, already on 0–1.
  • Both requests are fired in parallel with identical state; each round-trip is timed independently with performance.now(), so verdicts and RTT are directly comparable. Verdicts “agree” when both land on the same side of 0.5.
